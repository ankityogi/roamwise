🔐 Authentication Flow — JWT Lifecycle 
sequenceDiagram
    participant U as 📱 Flutter App
    participant S as 🔒 SecureStorage
    participant A as 🖧 /api/auth
    participant MW as 🛡️ JWT Middleware
    participant DB as 🍃 MongoDB

    Note over U,DB: 1️⃣ Registration / Login
    U->>A: POST /register or /login {name, email, password}
    A->>DB: Create user (bcrypt hash) or Verify credentials
    DB-->>A: User document
    A->>A: jwt.sign({id}, secret, {expiresIn: 30d})
    A-->>U: {user, token}
    U->>S: SecureStorage.write('token', jwt)

    Note over U,DB: 2️⃣ Authenticated API Request
    U->>S: SecureStorage.read('token')
    S-->>U: Bearer token
    U->>MW: GET /api/trips — Authorization: Bearer token
    MW->>MW: jwt.verify(token, secret)
    MW->>DB: User.findById(decoded.id).select('-password')
    DB-->>MW: User document
    MW->>MW: req.user = user
    MW-->>U: ✅ Proceed to controller → response

    Note over U,DB: 3️⃣ Session Expiry / Invalid Token
    U->>S: SecureStorage.read('token')
    S-->>U: Expired token
    U->>MW: GET /api/auth/profile
    MW->>MW: jwt.verify() ❌ FAILS
    MW-->>U: 401 Unauthorized
    U->>S: SecureStorage.delete('token')
    U->>U: Navigator → AuthScreen

📐 Key Architectural Decisions
Decision Rationale
Riverpod over BLoC Compile-safe dependency injection, no BuildContext dependency in business logic, testable StateNotifiers with immutable state
Dio over http package Built-in interceptors, retry support, request cancellation, structured error handling via DioException
JWT + SecureStorage Stateless authentication (no server sessions), tokens persisted in OS Keychain (iOS) / KeyStore (Android)
Gemini with retry backoff Exponential backoff on 429 rate limits prevents cascade failures during high traffic; max 3 retries
Platform-aware base URL Automatic loopback routing — 10.0.2.2 for Android emulator, localhost for iOS/desktop — zero config switching
MVC on backend Clean separation: Routes define endpoints, Controllers own business logic, Models define data schema + validation
Mongoose ODM Schema validation at application layer, pre-save middleware hooks (bcrypt), ref population, and compound index support
MVVM on frontend Views (Screens) observe ViewModels (Providers), Models are pure data classes — enables UI-independent testing
